# Feature reference

| Feature             | Page and behavior                                                                                                                                                                 | API                                                                                                                                       |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Public introduction | `/`: viewport hero, scroll fading, editorial collage and join CTA; authenticated visits redirect to discovery                                                                     | Session lookup on mount                                                                                                                   |
| Accounts            | `/auth?mode=signup` or `login`: labelled forms, confirmation and server validation, visibility toggle, success redirect                                                           | POST `/api/auth/register` with name/email/password/confirmPassword; POST `/api/auth/login` with email/password; both return `{user,csrf}` |
| Session             | Refresh retrieves user; guests on personal routes redirect to auth; logout deletes session                                                                                        | GET `/api/auth/me` returns `{user,csrf}` (null when guest); POST `/api/auth/logout` returns `{ok:true}`                                   |
| Search              | `/app`: search by recipe name or an exact category match; combined results are unique by recipe ID; URL preserves selected search; loading, retry and no-result states                                                                                 | GET `/api/recipes/search?q=` returns `{meals:[]}`                                                                                         |
| Category            | API-provided category chips; single active category                                                                                                                               | GET `/api/recipes/categories` returns `{categories:[{name,image}]}`; GET `/api/recipes/filter?category=`                                  |
| Ingredient          | One main ingredient only; spaces normalized for TheMealDB                                                                                                                         | GET `/api/recipes/filter?ingredient=` returns `{meals:[]}`                                                                                |
| Surprise            | Button opens a real random recipe; uncached on backend                                                                                                                            | GET `/api/recipes/random` returns `{meal}`                                                                                                |
| Details             | `/app/recipe/:id`: photo, category/area, checkable ingredients, original instructions and safe available tutorial link                                                            | GET `/api/recipes/:id` returns `{meal}`                                                                                                   |
| Favorites           | Card/detail heart saves/removes; `/app/cookbook` lists saved IDs resolved to recipes, safe partial-failure state                                                                  | GET `/api/favorites` returns `{ids:[]}`; POST with `{mealId}`; DELETE `/api/favorites/:mealId`                                            |
| Weekly plan         | `/app/planner`: reusable Monday–Sunday, one recipe/day; explore → details → Add to meal planner → day picker; replacements explicitly announced; every mutation saves immediately | GET `/api/planner` returns `{plan:[{day,mealId}]}`; PUT `/api/planner/:day` with `{mealId}`; DELETE same day                              |
| Shopping list       | Planner section derives separate entries for each ingredient and planned day, with original measurements; check, copy or print                                                    | Derived client-side from planned recipe details; no new endpoint                                                                          |

Authenticated favorites/planner writes return `{ok:true}` (favorite creation 201; planner and deletions 200). The normalized meal has `id`, `name`, `image`, `category`, `area`, `instructions`, `youtube`, and `ingredients:[{name,measure}]`. Summary filter cards may omit fields the source has not supplied. API failures are explicit; no fake recipes are substituted.

Native `dialog.showModal()` provides keyboard focus containment and Escape dismissal for the day picker. Responsive navigation uses an expanded-state button and real links. Public login/signup actions are always available in the top navigation, including the mobile menu. Reduced-motion users receive all text and static imagery without reveal transitions.
